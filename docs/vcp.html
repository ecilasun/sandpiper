Vector Coprocessor (VCP)

Home > SDK > VCP

Overview

The Vector Coprocessor (VCP) is a programmable hardware unit integrated within the Sandpiper VPU. It allows for custom vector processing operations that can execute in parallel with video scanout, making it ideal for effects like palette cycling, raster effects, and procedural graphics.

VCP programs are written using a custom instruction set and uploaded to the coprocessor for execution. The VCP has its own registers and can perform arithmetic, logic, palette manipulation, and conditional branching operations.

Data Structures

Buffer Size Enumeration

enum EVCPBufferSize {
    PRG_128Bytes  = 0,  // 32 instructions
    PRG_256Bytes  = 1,  // 64 instructions
    PRG_512Bytes  = 2,  // 128 instructions
    PRG_1024Bytes = 3,  // 256 instructions
    PRG_2048Bytes = 4,  // 512 instructions
    PRG_4096Bytes = 5   // 1024 instructions
};

Core Functions

VCPUploadProgram

void VCPUploadProgram(struct SPPlatform *ctx, const uint32_t* program, enum EVCPBufferSize size);

Uploads a VCP program to the coprocessor memory.

Parameters:

  • ctx - Pointer to the platform structure
  • program - Pointer to array of 32-bit VCP instructions
  • size - Size of the program buffer (EVCPBufferSize enum)

Notes: The program must be properly formatted using the VCP instruction set macros. The coprocessor must be stopped before uploading a new program.

VCPExecProgram

void VCPExecProgram(struct SPPlatform *ctx, const uint8_t execFlags);

Starts execution of the uploaded VCP program.

Parameters:

  • ctx - Pointer to the platform structure
  • execFlags - Execution control flags (4-bit value)

Notes: The execFlags parameter controls program execution behavior. Common values: 0x01 for standard execution.

VCPStatus

uint32_t VCPStatus(struct SPPlatform *ctx);

Queries the current status of the VCP.

Parameters:

  • ctx - Pointer to the platform structure

Returns: 32-bit status word containing execution state, program counter, and error flags

Status Word Format:

Bits [3:0]   - Error code
Bits [7:4]   - Current register
Bits [19:8]  - Program counter
Bits [21:20] - Program size (PRG)
Bits [22]    - Full flag (F)
Bits [23]    - Current flag (C)
Bits [27:24] - Output code

VCP Instruction Set

Command Codes

#define VCPSETBUFFERSIZE  0x0  // Set program buffer size
#define VCPSTARTDMA       0x1  // Start DMA operation
#define VCPEXEC           0x2  // Execute program

Instruction Opcodes

#define VCP_NOOP          0x00  // No operation
#define VCP_LOADIMM       0x01  // Load immediate value
#define VCP_PALWRITE      0x02  // Write to palette
#define VCP_WAITSCANLINE  0x03  // Wait for scanline
#define VCP_WAITPIXEL     0x04  // Wait for pixel position
#define VCP_MATHOP        0x05  // Math operation
#define VCP_JUMP          0x06  // Unconditional jump
#define VCP_CMP           0x07  // Compare
#define VCP_BRANCH        0x08  // Conditional branch
#define VCP_STORE         0x09  // Store to memory
#define VCP_LOAD          0x0A  // Load from memory
#define VCP_READSCANINFO  0x0B  // Read scan position
#define VCP_LOADPC        0x0C  // Load program counter
#define VCP_LOGICOP       0x0D  // Logic operation

Register Definitions

#define VREG_ZERO   0x0   // Constant zero
#define VREG_ONE    0x1   // Constant one
#define VREG_S0     0x2   // Saved register 0
#define VREG_S1     0x3   // Saved register 1
#define VREG_S2     0x4   // Saved register 2
#define VREG_S3     0x5   // Saved register 3
#define VREG_S4     0x6   // Saved register 4
#define VREG_S5     0x7   // Saved register 5
#define VREG_T0     0x8   // Temporary register 0
#define VREG_T1     0x9   // Temporary register 1
#define VREG_T2     0xA   // Temporary register 2
#define VREG_T3     0xB   // Temporary register 3
#define VREG_T4     0xC   // Temporary register 4
#define VREG_T5     0xD   // Temporary register 5
#define VREG_T6     0xE   // Temporary register 6
#define VREG_STATUS 0xF   // Status register

Condition Codes

#define COND_ALWAYS  0x0  // Always branch
#define COND_EQ      0x1  // Equal
#define COND_NE      0x2  // Not equal
#define COND_LT      0x3  // Less than
#define COND_LE      0x4  // Less than or equal
#define COND_GT      0x5  // Greater than
#define COND_GE      0x6  // Greater than or equal

Instruction Macros

Arithmetic Operations

vcp_add(dest, src1, src2)    // dest = src1 + src2
vcp_sub(dest, src1, src2)    // dest = src1 - src2
vcp_mul(dest, src1, src2)    // dest = src1 * src2
vcp_div(dest, src1, src2)    // dest = src1 / src2

Logic Operations

vcp_and(dest, src1, src2)    // dest = src1 & src2
vcp_or(dest, src1, src2)     // dest = src1 | src2
vcp_xor(dest, src1, src2)    // dest = src1 ^ src2
vcp_not(dest, src)           // dest = ~src

Data Movement

vcp_mv(dest, src)            // dest = src
vcp_clr(dest)                // dest = 0

Control Flow

vcp_noop()                              // No operation
vcp_jumpim(offset)                      // Jump to PC + offset
vcp_cmp(condition, reg1, reg2)          // Compare registers
vcp_branchim(offset)                    // Branch if condition true

Palette Operations

vcp_palette_write(index_reg, color_reg) // Write color to palette[index]

Synchronization

vcp_scanline_wait(line_reg)             // Wait until scanline == line_reg
vcp_scanline_read(dest_reg)             // Read current scanline to dest_reg

Example Usage

Simple Palette Cycling Program

#include "vcp.h"

// Program that cycles palette colors during scanout
uint32_t vcpprogram[] = {
    // Reset palette cycling
    vcp_clr(VREG_T0),                           // color = 0
    
    // Idle loop - wait for scanline 0
    vcp_scanline_read(VREG_6),                  // scanline = current
    vcp_cmp(COND_NE, VREG_6, VREG_ZERO),        // if scanline != 0
    vcp_branchim(-0x08),                        // branch to idle loop
    
    // Write palette entry
    vcp_loadimm(VREG_T1, 0xFF0000),             // color = red
    vcp_palette_write(VREG_T0, VREG_T1),        // palette[0] = red
    
    // Increment and loop
    vcp_add(VREG_T0, VREG_T0, VREG_ONE),        // color++
    vcp_jumpim(-0x20),                          // jump back
};

// Upload and execute
VCPUploadProgram(platform, vcpprogram, PRG_128Bytes);
VCPExecProgram(platform, 0x1);

// Check status
uint32_t status = VCPStatus(platform);
printf("VCP Status: 0x%08X\n", status);

Raster Bar Effect

// Program that changes palette during specific scanlines
uint32_t rasterprogram[] = {
    vcp_clr(VREG_S0),                           // color_index = 0
    vcp_loadimm(VREG_S1, 100),                  // target_line = 100
    
    // Wait for target scanline
    vcp_scanline_read(VREG_T0),
    vcp_cmp(COND_LT, VREG_T0, VREG_S1),
    vcp_branchim(-0x08),
    
    // Change palette at scanline
    vcp_loadimm(VREG_T1, 0x00FF00),             // green
    vcp_palette_write(VREG_S0, VREG_T1),
    
    // Continue to next frame
    vcp_scanline_read(VREG_T0),
    vcp_cmp(COND_EQ, VREG_T0, VREG_ZERO),
    vcp_branchim(-0x08),
    
    vcp_jumpim(-0x28),                          // loop
};

Programming Guidelines

Best Practices

  • Always stop before upload: Use VPUWriteControlRegister to stop existing programs before uploading
  • Program size: Choose appropriate buffer size - larger programs allow more complex effects but use more memory
  • Timing coordination: Use scanline wait instructions to synchronize with video output
  • Register usage: Use S-registers (S0-S5) for values that persist across frames, T-registers (T0-T6) for temporary values
  • Infinite loops: Most VCP programs run in infinite loops, synchronized to vsync

Common Patterns

  • Frame sync: Wait for scanline 0 to detect new frame
  • Scanline effects: Wait for specific scanlines and modify palette or other parameters
  • Conditional execution: Use compare and branch for state-based effects
  • Incremental changes: Use add/sub to create smooth transitions or animations

Performance Considerations

  • VCP instructions execute in parallel with CPU, minimizing performance impact
  • Palette writes are synchronized with video scanout to prevent tearing
  • Keep programs as small as possible for optimal performance
  • Use immediate values when possible to reduce memory reads

Error Codes

Status register error codes (bits [3:0]):

  • 0x0 - No error, running normally
  • 0x1 - Invalid instruction
  • 0x2 - Division by zero
  • 0x3 - Invalid register access
  • 0x4 - Program counter out of bounds
  • 0xF - General fault
